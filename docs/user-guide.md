## 系统概述

VALTRIX网站后台管理系统是一个功能完整的企业官网内容管理平台，支持：

- **内容管理**：产品、新闻、资源、行业方案、服务内容、成功案例、常见问题、招聘职位、关于我们、菜单、分类，以及**通用内容类型**（可自定义内容类型与字段）
- **多语言**：六语种（中/英/日/韩/法/阿），一键翻译与批量翻译、翻译配置；阿拉伯语 RTL 自动适配
- **商机与成交**：留言线索、下载留资、询价报价单（PDF 下载与邮件发送）、考察预约、客服工单
- **会员体系**：会员中心（前台注册/登录/收藏/订单/报价/下载/发票/地址）、会员等级与积分、会员管理（后台）
- **在线商城**：商品与分类、库存、阶梯价、优惠券、订单与发货、销售统计
- **营销与 SEO**：EDM 邮件营销、外链营销、SEO/GEO 配置、Sitemap、搜索引擎收录推送
- **数据统计**：访客统计、转化漏斗、页面热力图、运营驾驶舱
- **平台化能力**：插件/能力市场（启停中心）、对外 API 网关、AI 开关矩阵、模板系统（多套风格一键切换）、行业包一键初始化、AI 建站向导、多租户/多站点、品牌 OEM 白标
- **AI 能力**：AI 智能客服（知识库 + RAG + 全网大数据收集）、AI 内容生成/润色/配图、AI 自动运营、AI 用量统计
- **运维与安全**：数据库备份与恢复、一键部署、在线/离线增量更新、操作日志、通知中心、服务器安全配置清单
- **权限管理**：**细粒度权限码**（当前 80 个）+ 角色（管理员 / 内容维护人员），侧边栏按权限自动过滤入口

**访问地址**: `/admin`
**技术栈**: Next.js 14 + Prisma + PostgreSQL + Tailwind CSS

## 登录与权限

### 登录
1. 访问 `/admin/login`
2. 输入用户名和密码
3. 点击登录

### 角色权限

后台采用**细粒度权限码**模型（不是"管理员 / 普通用户"两档），当前共 **80 个权限码、2 个角色**：

| 角色 | 权限码 | 权限范围 |
|------|--------|---------|
| **管理员**（admin） | **80 个（全部）** | 所有模块 + 全部系统设置、权限管理、部署/备份/更新、授权管理 |
| **内容维护人员**（editor） | **35 个** | 内容模块（产品/新闻/资源/行业方案/服务/成功案例/常见问题/招聘/关于/菜单/分类）、运营数据（留言线索、下载留资、访客统计、漏斗、热力图）、会员与交易（会员、会员等级、商城订单、报价单、客服工单）、以及共用能力（上传文件、机器翻译） |

**权限码格式 = 「模块:动作」**（如 `product:view`、`config:site`、`file:upload`、`translate:use`）。
后台有**两张**"路径 → 权限码"表：一张管**后台页面**、一张管**后台接口**；两者都按**最长前缀**匹配，
**没有匹配到的路径只要求登录**。

**侧边栏会自动按权限过滤入口**：没有对应权限的菜单项**不显示**（含二级、三级菜单，以及插件提供的入口）。
实测（2026-09-16）：同一个后台，**内容维护人员可见 35 个入口，管理员可见 69 个入口**。

**无权限时的表现（便于排查）**：

| 情况 | 表现 |
|---|---|
| 未登录访问后台页面 | 跳转登录页（带 callbackUrl） |
| 未登录调用后台接口 | **401** JSON |
| 已登录但**页面**无权限 | **403** 页面（不跳登录页） |
| 已登录但**接口**无权限 | **403** JSON：`{"error":"无权限访问"}` |

#### 如何调整权限（运维）

权限清单**只有一个真源**：`prisma/permission-catalog.json`。

1. **给角色增删权限**：编辑该文件的 `editorCodes`（内容维护人员的权限码数组）；
2. **应用**：`node scripts/seed-permissions.js` —— 它会补建缺失的权限码，并把两个角色的权限对齐到该文件；
3. **让使用者重新登录**（见下方红框）。

> ⛔ **改权限后必须重新登录才生效。**
> 权限是在**登录那一刻**写进会话凭据的；只改数据库的话，已登录用户的会话里仍是**旧权限集**，
> 表现为"明明改了却没生效"（侧边栏没变化、接口仍 403）。**这一点在生产部署时尤其重要**：
> **先跑 seed → 再发代码 → 然后通知所有人重新登录。**

#### 已知限制：部分入口"能进去、但数据 403"（2026-09-16 实测）

有一批由**插件**提供的后台入口，**页面本身没有登记权限**（⇒ 任何已登录账号都能打开、侧边栏也会显示），
但它们的**数据接口是有权限的** ⇒ 权限不足的用户点进去会看到**空白/报错页面**。实测（同一次探测用三种身份对照）：

| 入口 | 页面可否打开（内容维护人员 / 零权限账号） | 数据接口 | 结果 |
|---|---|---|---|
| 多站点 `/admin/sites`、多租户 `/admin/tenants` | 可打开 / 可打开 | 需 `config:site` | ⚠️ 权限不足时数据 403 |
| 外链营销 `/admin/backlinks`、外链文案 `/admin/backlinks/posts` | 可打开 / 可打开 | 需 `seo:view` | ⚠️ 同上 |
| 商城优惠券 `/admin/shop/coupons` | 可打开 / 可打开 | 需 `config:site` | ⚠️ 同上 |
| AI 知识库 `/admin/ai-knowledge`、AI 建站向导 `/admin/ai-site-wizard` | 可打开 / 可打开 | 需 `ai:config` | ⚠️ 同上 |
| 运营驾驶舱、漏斗、热力图 | 可打开 / 可打开 | 需 `analytics:view` | 内容维护人员**正常**；零权限账号才会空白 |
| 商城分类、批量翻译 | 可打开 / 可打开 | 需 `product:view` / `translate:use` | 内容维护人员**正常**；零权限账号才会空白 |
| （对照）会员管理、通知中心 | 分别 403 / 403 | 与页面同码 | ✅ 页面与接口一致 |

**性质说明**：这不是数据泄露（接口都拦住了），而是**入口可见性与页面门闩不一致** ——
即"能进去但全是 403"的空壳页，容易被误当成**故障**。
**如需按权限隐藏这些入口**：需为这些页面补登「页面 → 权限码」条目（与接口用同一个码），属**开发侧改动**，请联系维护方；
登记在 `docs/backend/09-admin-permission-plan-20260916.md` 的「已知情 / 待决策」中。

## 内容管理

### 通用功能块（所有内容模块共用）

所有内容模块（产品/新闻/行业/服务/职位/关于/资源）共用统一的多语言编辑能力：

| 功能 | 说明 |
|------|------|
| 多语言字段 | 每个文本字段支持 6 语种（中/英/日/韩/法/阿），通过语言标签切换编辑 |
| 一键翻译栏 | 页面顶部自动翻译栏，点击"一键翻译全部"将中文翻译为所有启用语种 |
| 自动翻译 | 开启后，输入中文 1.5 秒后自动翻译（需在翻译配置中开启） |
| SEO/GEO配置 | 自动提取关键词，支持 GEO 地区和城市多选 |
| 富文本编辑器 | 支持多语言富文本，保持排版结构 |
| 数组编辑器 | jsonArray/stringArray 类型字段用可视化数组编辑器，支持逐项翻译 |

**字段命名规则**: 中文字段为基础名（如 `name`），其他语种为基础名+语种后缀（如 `nameEn`/`nameJa`/`nameKo`/`nameFr`/`nameAr`）。

**日文代号**: 系统内部统一使用 `ja`（ISO 639-1），百度翻译 API 内部自动转换为 `jp`。

**图片上传（统一压缩）**: 后台所有图片上传均经统一接口处理——自动压缩转 WebP 适配网页（大图最长边 1600px、质量 80，另生成 400px 缩略图），GIF/SVG 原样保留，单文件上限 20MB。后台各图片字段均标注了推荐尺寸/比例与格式（如页头背景推荐 1920×600）。**后台未上传图片时，前台自动使用与主题匹配的网络占位图**，不会出现空白或破图。

### 通用内容类型管理

> 通用内容类型是系统的**扩展能力**：无需写代码，在后台可视化地创建任意内容栏目（如合作伙伴、案例库、荣誉资质、团队介绍等），自动获得与产品/新闻同级的增删改查、六语种多语言、SEO、发布状态与前台渲染。

#### 入口与页面
- 路径: `/admin/content-types`（内容管理 → 内容类型管理）
- 页面显示全部内容类型：**内置类型**（系统自带：产品/新闻/服务/行业/职位/关于/资源/FAQ/案例）与**动态类型**（后台新增），每张卡片展示字段清单，并可直接进入「内容管理」「前台预览」。

#### 新增内容类型（三步）
1. 点击「新增类型」，填写：**类型标识**（英文字母数字下划线，全站唯一，用于 URL）、**类型名称**（六语种）、**标题字段**（列表/详情页用哪个字段当标题）、**URL 标识字段**（生成访问链接的 slug 来源）、是否启用状态管理、排序。
2. 在字段编辑器中点击「+ 添加字段」，逐条配置字段类型（见下表）。
3. 保存后，左侧「内容管理」下拉即出现该类型入口，可像产品/新闻一样维护内容。

#### 字段类型一览
| 字段类型 | 说明 |
|----------|------|
| 文本 text | 单行文本，可勾选多语言 |
| 多行文本 textarea | 多行文本，可勾选多语言 |
| 富文本 richtext | 富文本编辑器（排版/图片），可勾选多语言 |
| 图片 image | 上传图片（统一压缩适配 Web），未上传时前台自动网络占位图 |
| 数字 number | 数值字段 |
| 开关 boolean | 是/否 |
| 下拉 select | 预设选项单选 |
| 数组 stringArray | 多行文本列表（如产品特性），可逐项多语言 |
| 对象数组 jsonArray | 结构化子字段（如技术参数 label/value 对），子字段可多语言 |

**多语言**：勾选「多语言」的字段，编辑时显示六语种标签页，支持一键翻译；数据以 `{zh,en,ja,ko,fr,ar}` 对象存储，前台自动按当前语种显示。

#### 管理内容

## AI 智能客服

前台右下角悬浮的 AI 客服，基于「知识库 + DeepSeek 大模型」回答访客问题，支持六语种，命中报价/联系/购买等意图时引导留资转人工。

### AI 客服知识库
- 路径: `/admin/ai-knowledge`（内容管理 → AI 客服知识库）
- **知识条目**: 每条含标题（问题）+ 内容（答案）+ 分类 + 标签 + 来源 + 状态 + 排序，标题与内容均支持六语种
- **状态控制**: 仅「启用(published)」条目对 AI 客服生效；「停用(draft)」不参与回答
- **四种写入方式**:
  1. **手动创建**: 点击「新建知识条目」逐条录入
  2. **文档上传导入**: 支持 txt / md / docx / pdf / html，AI 自动按片段提炼 2-5 个「问题+答案」问答对入库
  3. **按关键词 AI 生成**: 输入行业/产品关键词（如"金刚石热沉、半导体"），AI 自动围绕主题生成 3/5/8/10 条问答
  4. **全网自动采集**: 从配置的采集源定时抓取行业内容入库（来源标记为"全网收集"）
- **一键翻译全部语种**: 编辑条目内点击按钮，自动把中文标题+内容翻译为 5 个外语种，**实时显示逐语种进度**（如"正在翻译 英文 (1/5)..."）；已有内容的语种自动跳过不重复翻译
- **多语言**: 系统自动抽取的产品/新闻/服务/应用领域/FAQ 内容，也会随知识库一起供 AI 检索回答
- **使用机制**: 访客发消息时，系统读取启用的知识条目（最多 40 条）+ 产品/新闻/服务/领域/FAQ，按访客语种拼入 AI 上下文，AI 仅据此作答、不编造

### AI 客服人机验证
- 前台打开 AI 客服窗口，先弹出数学验证码卡片，验证通过后才会显示欢迎语并可对话
- 底部固定显示说明:「AI 智能回复仅供参考，请以官网正式信息为准」（六语种）
- 防止机器人/爬虫刷量占用 AI 额度

### AI 欢迎语
- 后台「AI 客服设置」中配置客服名称与欢迎语（六语种）
- 点击「✨ AI 一键生成欢迎语」自动为六个语种生成得体的问候语并填入

### 提交类防刷
- 所有前台提交类事件（询价、考察预约、订阅、下载留资、留言、AI 客服对话等）均已内置频率限制
- 默认策略: 同一 IP 每分钟 5 次（AI 客服对话 15 次、下载验证码 10 次），超限返回 429 提示稍后再试

## 常见问题

### 翻译后内容丢失/无法保存
- 检查对应模型的 Prisma schema 是否有全语种字段（如 titleJa/titleKo 等）
- 检查后端 POST/PUT API 是否接收并保存了全部多语言字段
- 改 schema 后需执行 `npx prisma db push` 并重启 dev server

### 前台切换语言后仍显示中文
- 检查该语种是否在后台语种管理中启用
- 检查该内容是否有对应语种的翻译数据
- 静态区块标题（如"岗位职责"）目前仅支持中英，其他语种回退中文

### 阿拉伯语版面是镜像的
- 这是正常的，阿拉伯语国际惯例为从右往左（RTL）排列
- 箭头、菜单、表单均已自动适配 RTL

### 构建失败（内存不足）
- 增加 swap 分区: `fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`

### 页面 502 Bad Gateway
- 检查 PM2 进程: `pm2 status`
- 查看日志: `pm2 logs zuowen-website`
- 确认端口 3000 正在监听

### 登录后 Session 丢失
- 检查 `.env` 中 `NEXTAUTH_URL` 是否与实际访问域名一致（含 http/https）

   - 构建项目（pnpm build）

### 系统更新（代码版本升级）

**入口**：后台 → 系统部署 → 系统更新（/admin/system-update）

**用途**：升级系统代码版本，支持上传升级包或在线升级。

**升级包格式**：
- .zip 压缩包，内含 manifest.json 和需要更新的文件
- manifest.json 格式：
```json
{
  "version": "1.1.0",
  "releaseNotes": "更新说明",
  "files": ["app/page.tsx", "components/..."],

```

**方式一：上传升级包**
1. 进入「系统更新」页面
2. 点击「选择升级包」，上传 .zip 文件

4. 升级前自动备份数据库到 backups/pre-upgrade-*.json
5. 按文件列表覆盖代码（自动跳过 node_modules、.env、uploads、backups 等保护目录）
6. 如有迁移脚本则自动执行

8. **重启服务使改动生效**

**方式二：在线升级**
1. 在 .env.local 中配置 UPDATE_SERVER_URL（远程更新服务器地址）
2. 点击「检查更新」，系统连接远程服务器获取最新版本
3. 如发现新版本，显示更新说明和下载地址
4. 点击「在线升级」，自动下载并执行升级流程

**方式三：增量更新（推荐日常使用）**
- 通过供应商提供的增量更新脚本，仅对比并上传**有变化的文件**，秒级完成，避免每次整包上传
- 适用场景: 日常代码 / 静态资源 / 配置的小改动
- 有数据库结构变化（schema）时自动执行 prisma db push；有代码变化时自动构建并重启服务；仅静态文件变化时不重启
- 首部署或大版本升级仍使用整包部署（一键部署 → 上传部署包）

**升级包制作**：

**回滚方法**：
1. 升级前自动备份的数据库文件在 backups/pre-upgrade-*.json

3. 恢复数据库：使用「一键部署」页面的「恢复」功能

### 上传部署方式

**适用场景**：远程服务器没有配置 Git 仓库，或需要直接上传本地代码包部署。

**使用步骤**：
1. 进入「一键部署」页面
2. 选择目标服务器
3. 部署方式选择「上传部署」
4. 点击「选择文件」，上传本地 .zip 格式的代码包（最大 200MB）
5. 点击「开始上传部署」
6. 系统自动执行：
   - 上传代码包到服务器 /tmp 目录
   - 解压到部署目录
   - 安装依赖（pnpm install --prod）
   - 数据库同步（prisma db push）
   - 构建项目（pnpm build）
   - 重启服务（PM2 / systemd）
   - 健康检查

**代码包制作要求**：
- 必须是 .zip 格式
- 包含完整的项目代码（app/、components/、lib/、prisma/、public/、package.json 等）
- 不需要包含 node_modules、.next、.env 等文件
- 建议在本地执行 `pnpm build` 验证无误后再打包

**Git 拉取 vs 上传部署**：

| 对比项 | Git 拉取 | 上传部署 |
|--------|----------|----------|
| 代码来源 | 远程 Git 仓库 | 本地上传 .zip |
| 适用场景 | 服务器已配置 Git | 无 Git 仓库或临时部署 |
| 部署速度 | 快（只拉取差异） | 较慢（上传完整包） |
| 版本控制 | 自动记录 commit | 需手动管理版本 |
| 回滚 | git revert | 重新上传旧版本 |

**注意事项**：
- 上传部署会覆盖服务器上的代码文件
- 部署前建议先备份数据
- 大文件上传可能需要较长时间
- 部署过程中请勿关闭页面

## 性能优化

> 2026-09-02 上线。目标：减少服务器压力、提升访问速度、保障高并发稳定。
> 详细方案见 `docs/performance-optimization.md`。

### 1. API 响应缓存层（已生效）

前台页面为客户端渲染，数据通过公开 API 获取。为避免每个请求都实时查询数据库，公开 API 已统一加入缓存头（`lib/api-cache.ts`）：

| 数据 | 缓存策略 |
|------|----------|
| 语种 / 菜单 | 1 小时强缓存 |
| 首页 / 站点 / 页面配置 | 5 分钟 + 异步刷新（SWR） |
| 产品 / 行业 / 服务 / 关于 / 资源 / 职位 | 5 分钟 + 异步刷新（SWR） |
| 新闻（含自动采集） | 1 分钟 + 异步刷新 |

- 效果：浏览器 / CDN 复用响应，不再每次打数据库。
- 后台修改数据后最多 5 分钟前台可见（SWR 异步刷新机制，不会永久缓存）。
- **注意**：如果后台修改了数据，前台没立刻变化，这是正常的，等缓存过期（最多 5 分钟）自动刷新；急用可重启服务强制清缓存。

### 2. 数据库连接池优化（已生效）

- 所有 API 统一使用 Prisma 全局单例（`@/lib/prisma`），避免每个 API 各自开连接池导致连接数爆炸。
- 生产环境连接数控制：在 `.env` 的 `DATABASE_URL` 后追加 `&connection_limit=10`（按机器配置调整）。
- 高并发场景可接 PgBouncer（事务级连接池，见文档）。

### 3. Nginx gzip 压缩与缓存（生产部署用）

配置文件：`docs/nginx-zuowen.conf`

- gzip 压缩：文本 / JS / CSS / JSON 等，减少传输体积 60-80%。
- 静态资源长缓存：`/_next/static/` 一年（文件名带哈希，内容永不变）。
- uploads 图片缓存 7 天、字体一年。
- HTTPS 强制跳转、安全响应头。

**部署步骤**：
1. 拷贝到服务器 `/etc/nginx/conf.d/zuowen.conf`
2. 把 `example.com` 替换为真实域名，`ssl_certificate` 换成证书路径
3. 执行 `nginx -t` 校验，`systemctl reload nginx` 生效

### 4. CDN 加速静态资源（生产部署用）

方案文档：`docs/cdn-acceleration.md`

- 使用阿里云 OSS + CDN，加速 `/_next/static/` 与 `/uploads/` 静态资源。
- API 缓存头已兼容 CDN（`s-maxage` 生效），CDN 也会缓存 API 响应。
- 按流量计费，小型企业官网成本很低。
- CDN 加速域名需要 ICP 备案。

### 5. 日志与临时文件清理

- **Linux 生产**：`scripts/cleanup.sh`，crontab 每天凌晨 3 点执行：
  ```bash
  crontab -e
  # 加入
  0 3 * * * /bin/bash /var/www/zuowen/scripts/cleanup.sh >> /var/log/zuowen-cleanup.log 2>&1
  ```
- **Windows 本地**：`scripts/cleanup.ps1`，可配合「任务计划程序」每日执行。
- 清理内容：`.next/cache`、超过 14 天的日志、临时部署包、保留最近 10 份备份。

### 6. 服务器资源监控

- **Linux 生产**：`scripts/monitor.sh`，每 5 分钟监控：
  - CPU 使用率 > 85% 告警
  - 内存使用率 > 85% 告警
  - 磁盘使用率 > 80% 告警
  - 系统负载 > 核数告警
  - 网站服务不可访问告警（可配置自动重启）
  - 超阈值通过飞书 webhook 推送告警（配置 `ALERT_WEBHOOK`）
  - crontab 每 5 分钟执行：`*/5 * * * * /bin/bash /var/www/zuowen/scripts/monitor.sh`
- **Windows 本地**：`scripts/monitor.ps1`，任务计划程序每 5 分钟执行，日志写入 `logs/monitor.log`，告警写入 `logs/monitor-alert.log`。

### 7. 部署后验证清单

```bash
# gzip 生效
curl -I -H "Accept-Encoding: gzip" https://yourdomain.com/
# 应返回 Content-Encoding: gzip

# 静态资源长缓存
curl -I https://yourdomain.com/_next/static/chunk.js
# 应返回 cache-control: max-age=31536000, immutable

# API 缓存头
curl -I https://yourdomain.com/api/public/languages
# 应返回 Cache-Control: public, s-maxage=3600
```

### 8. 关于"Next.js 静态生成 / ISR"

前台页面为客户端渲染（CSR），页面 HTML 本身不含业务数据（数据都在客户端 fetch），所以**静态生成/ISR 对当前架构直接收益有限**，暂不实施。如需进一步优化可改为服务端组件 + `generateStaticParams`（涉及前台组件重构，见性能优化文档"进阶优化"）。

## 服务器安全配置

> 适用：生产服务器（阿里云 ECS / 腾讯云等 Linux 服务器）。**部署上线前务必完成**。

### 1. SSH 密钥登录，禁用密码登录

SSH 密钥比密码更安全，密钥不可暴力破解。

**本机生成密钥对**（Windows PowerShell）：
```powershell
ssh-keygen -t ed25519 -C "your_email@example.com"
# 一路回车，会生成 ~/.ssh/id_ed25519（私钥）和 id_ed25519.pub（公钥）
```

**上传公钥到服务器**：
```bash
ssh-copy-id -i ~/.ssh/id_ed25519.pub root@你的服务器IP
# 或手动：把 id_ed25519.pub 内容追加到服务器 ~/.ssh/authorized_keys
```

**禁用密码登录**（编辑服务器 `/etc/ssh/sshd_config`）：
```ini
PasswordAuthentication no
PubkeyAuthentication yes
```
保存后重启 SSH：`systemctl restart sshd`

> ⚠️ 确认密钥能正常登录后，再执行"禁用密码登录"这一步，防止把自己锁在门外。

### 2. 修改 SSH 默认端口（22 → 其他端口）

修改 `/etc/ssh/sshd_config`：
```ini
Port 22022
```
保存后重启 SSH，之后登录需指定端口：
```bash
ssh -p 22022 root@你的服务器IP
```
**记得同步更新防火墙放行新端口，并关闭 22 端口。**

### 3. 配置防火墙（ufw），只开放必要端口

以 Ubuntu 为例（ufw）：
```bash
# 安装并启用
apt install ufw -y
ufw default deny incoming
ufw default allow outgoing

# 放行必要端口
ufw allow 22022/tcp        # SSH（你修改后的端口）
ufw allow 80/tcp            # HTTP
ufw allow 443/tcp           # HTTPS
ufw allow 3000/tcp          # 如果 Next.js 直连（建议用 Nginx 反代则不需要开）

# 启用
ufw enable
ufw status
```

> 安全原则：**只开放对外服务需要的端口**，数据库（5432）、管理后台等不对外网开放（仅内网/白名单）。

### 4. 启用自动安全更新

**Ubuntu/Debian**：
```bash
apt install unattended-upgrades -y
dpkg-reconfigure --priority=low unattended-upgrades
# 选择"是"，自动安装安全更新
```

**CentOS/Rocky**：
```bash
dnf install dnf-automatic -y
systemctl enable --now dnf-automatic.timer
```

### 5. 配置 SSL 证书（Let's Encrypt 免费证书）

使用 certbot 自动申请并续期：
```bash
# 安装 certbot + Nginx 插件
apt install certbot python3-certbot-nginx -y

# 自动申请证书并配置 Nginx HTTPS
certbot --nginx -d example.com -d www.example.com

# 测试自动续期（Let's Encrypt 证书 90 天有效）
certbot renew --dry-run
```
申请成功后，Nginx 会自动配置 HTTPS 跳转，无需手动管理证书（自动续期）。

### 6. 定期备份数据库和重要文件

- 后台「一键部署」页面的**一键备份**可手动备份（数据库 .dump + 项目文件 .zip）。
- 建议**每日自动备份**到异地/对象存储（OSS）：
  - Linux：crontab 每日执行备份脚本（参考 `scripts/cleanup.sh` 所在项目备份逻辑）
  - 数据库：`pg_dump` 每日导出；文件：打包关键目录
  - 备份上传到阿里云 OSS / 腾讯云 COS，防止服务器硬盘故障丢数据
- 升级前系统会自动备份（backups/pre-upgrade-*.json），可作为回滚点。

### 7. 配置日志监控和告警

- 服务器资源监控：`scripts/monitor.sh`（CPU/内存/磁盘/服务健康，超阈值飞书告警），见「性能优化」章节。
- 系统登录日志：`journalctl -u ssh` 或 `/var/log/auth.log`，定期检查异常登录。
- 建议接入云厂商云监控（阿里云云监控 / 腾讯云云监控），配置 CPU/内存/带宽告警。
- 重要文件访问监控（可选）：`auditd` 审计，记录敏感文件操作。

- [ ] 自动安全更新已启用

## 十、商用授权

本系统支持商用授权（授权码 + 域名绑定，离线验证）。

### 首次 30 天试用
新客户首次合作默认提供 **30 天试用授权**（试用版）。试用授权码由授权方签发，绑定您的站点域名。
试用到期后系统会提示续期，功能不受影响；正式购买后授权方提供新授权码，在下文激活即可，无需重装。

### 激活授权
1. 登录后台 → 左侧「系统部署 → 授权管理」。
2. 将授权方提供的授权码粘贴到输入框，点击「激活授权」。
3. 激活成功后显示授权信息（被授权方/版本/绑定域名/到期时间）。

### 授权状态说明
- 已授权（有效）：正常使用全部功能。
- 未授权：后台顶部显示黄色提醒横幅，不影响编辑功能，请尽快激活。
- 已过期：请联系授权方提供新授权码，重新激活即可。
- 域名不匹配：当前站点域名不在授权范围，需联系授权方重新签发。

### 解除授权
在「授权管理」页点击「解除授权」。解除后系统回到未授权状态。

### 授权方（系统供应商）签发授权码
授权码的生成方法属供应商内部资料，见《授权签发与授权管理指南》（内部文档，不随部署包分发），此处不再赘述。

## 十一、通用功能平台 + 插件模型（能力市场）

> 系统采用「**通用功能平台 + 内容功能模块 + 能力市场插件**」三层架构。平台提供基础能力，内容模块负责站点内容，插件以开关/配置方式挂载各类能力，可按需启停、无限扩展。

### 1. 三层架构总览

| 层级 | 定位 | 内容 |
|------|------|------|
| **通用功能平台** | 全站公共底座 | 用户/角色/权限、站点设置、多语言、SEO、上传、SMTP、日志、部署/备份/更新、通知中心 |
| **内容功能模块** | 站点内容 | 产品/新闻/行业/服务/案例/FAQ/关于/招聘/资源 + **通用内容类型**（后台可视化建栏目，无需改代码） |
| **能力市场插件** | 可插拔能力 | AI 智能客服、AI 翻译、SEO、内容采集、邮件营销、外链回链、访客统计、验证码防刷、询价报价、考察预约、下载留资、模板管理、会员中心（规划）、在线商城（规划）等 |

### 2. 插件管理（后台 → 系统设置 → 插件管理）

- 插件按 **AI / 内容 / 营销 / 数据 / 系统 / 集成** 分类展示，每个插件卡片含：名称、说明、版本、启用开关、配置按钮、管理入口、权限声明。
- **启停**：关闭某插件 = 隐藏对应后台菜单入口 + 关闭前台对应功能（如关闭「AI 智能客服」，前台悬浮客服按钮消失）。内置插件不可卸载，仅可启停。
- **配置**：插件的配置弹窗按 manifest 自动渲染（文本/密码/开关/下拉/数字），保存写入 `site_config.plugin_state`。
- **规划中插件**：会员中心、在线商城、前台模板市场已登记在能力市场，默认停用，启用后可扩展对应功能。

### 3. 内容字段类型（通用内容类型可选的字段）

内容类型定义字段支持：`text`（多行/富文本多语言）、`stringArray`/`jsonArray`（数组）、`image`（图片）、**`video`（视频：URL 或上传，详情页内嵌播放）**、**`gallery`（图集：多图，列表用首图作封面）**、`boolean`、`number`、`select`、`relation`（关联下拉）、`datetime`。

### 4. 插件间通信机制（供二次开发）

- **能力注册表（SPI）**：`lib/plugins/capabilities.ts`。插件「声明提供能力」（如 `smtp.send` / `seo.push`），其他模块通过 `callCapability(name, args)` 统一调用——进程内函数调用、不关心实现方、可整体替换实现。
- **事件总线**：`lib/plugins/events.ts`。异步联动走 `emit('content.published' | 'lead.submitted' | ...)`，订阅者可多个、可增删，发布者不感知订阅者。
- **内置能力注册**：`lib/plugins/boot.ts`（smtp.send / smtp.configured / seo.push）。
- **对外 API 网关（规划）**：外部系统/第三方通过 REST + API Key 调用插件能力，统一鉴权/限流/审计。

### 5. 新增一个插件的最小步骤（二次开发参考）

1. 在 `lib/plugins/registry.ts` 的 `BUILTIN_PLUGINS` 登记 manifest（key/name/description/category/version/defaultEnabled/configFields/permissions/adminUrl）。
2. 实现功能页面与 API（或复用现有模块）。
3. 如需被其他插件调用：在 `boot.ts` `registerCapability()` 注册能力；如需响应联动：`events.ts` 订阅事件。
4. 在 `AdminSidebar.tsx` 菜单项加 `plugin: '你的插件key'`（插件停用时自动隐藏入口）。

### 6. 对外 API 网关（插件能力 REST 对外开放）

- 入口：后台 → 系统设置 → 插件管理 → 顶部「对外 API 网关」区块。
- 用途：第三方系统 / 外部应用通过 REST 调用「对外开放」的插件能力（当前开放：`seo.push` 百度推送）。
- 调用方式：`POST /api/integration/[capability]`，请求头 `X-API-Key: <key>`，body `{ "args": {...} }`。
- 鉴权与安全：Key 后台生成/删除（`zw_` 前缀，删除立即失效）；每 Key 每分钟 60 次限流；调用记录写入 `data/gateway-audit.jsonl`（时间/Key/IP/能力/结果）。
- 能力开放标记：`lib/plugins/capabilities.ts` 注册能力时传 `{ public: true }` 即对外开放（默认不对外，安全默认）。

### 7. AI 能力插件族（全站 AI 开关矩阵）

> 升华方向：**AI 不是单个客服插件，而是一族底层能力插件**，全站任意功能可嵌入「AI 开关」，最终实现网站自动运营。

- **插件族**：`AI 文本`（内容生成/改写/SEO 文案）、`AI 图像`（占位图/配图生成，规划中）、`Chat AI`（AI 智能客服）、`AI 翻译`、`AI 自动运营`（规划中）。
- **统一 AI 网关**：`lib/ai/gateway.ts`。两层开关控制任一 AI 能力：①全局 AI 开关（`ai_global_config.enabled`，关=所有 AI 能力不可用）②各 AI 插件开关（插件市场启停）。判断入口 `aiCapabilityEnabled(pluginKey)`。
- **文本 AI 调用**：`callAiText(prompt)`（DeepSeek 兼容 API，密钥自动回退读取翻译/AI 客服配置）。
- **已接线**：AI 智能客服同时受「全局 AI 开关 + Chat AI 插件开关 + 客服自身开关」三重控制。
- **自动运营蓝图（AI 自动运营插件，规划中）**：定时流水线「内容采集 → AI 翻译 → AI 生成摘要/SEO 标题 → 自动发布 → 搜索引擎推送」，配合事件总线（`content.published` → 自动百度推送）实现网站自动更新运营，适配多终端多平台。

### 8. 事件总线联动（已启用）

- 动态内容发布/更新（`/api/admin/content/[type]` POST / [id] PUT，status=published 时）自动触发 `content.published` 事件 → 自动推送百度收录。无需额外配置，发布即推送。

### 9. AI 开关矩阵（每个功能独立 AI 开关）

> 升华落地：**AI 开关下沉到每个具体功能点**——不只是插件开关，而是「写文章 / 润色 / 摘要 / AI 翻译 / SEO 填充 / 客服问答 / AI 配图」等每个功能都能独立开/关。

- **入口**：后台 → 内容工具 → **AI 开关矩阵**（或系统设置 → AI 开关矩阵）。
- **三层开关**（全部开启该功能才可用）：
  1. **全局 AI 总闸**（页面右上角）：关 = 全站所有 AI 能力不可用（一键停用）。
  2. **AI 插件族开关**（插件管理 → AI 文本 / AI 翻译 / SEO / Chat AI / AI 图像 / AI 自动运营）。
  3. **功能点开关**（本页逐项）：AI 写文章 / AI 润色改写 / AI 摘要·SEO / AI 自动翻译 / SEO·GEO 一键填充 / AI 客服问答 / AI 占位配图（规划）/ 采集 AI 处理（规划）。
- **内置功能点**：editor_generate（写文章）、editor_polish（润色）、editor_summary（摘要/SEO）、translate_auto（自动翻译）、seo_fill（SEO 填充）、chat_answer（客服问答）、image_placeholder（占位配图）、collect_ai（采集处理）。
- **已嵌入的功能**：
  - 内容表单（产品/新闻/案例/行业/服务/荣誉等通用内容类型）顶部 **「AI 写作助手」**：选字段 + 语种 + 写/润色/摘要 → AI 生成 → 一键回填该字段该语种。
  - 单语文本字段右侧 **「AI」按钮**：写 / 润色 / 摘要回填。
  - **富文本编辑器（详情正文）**：编辑器上方 **AI 润色 / 摘要 / 生成** 工具条——对当前正文一键润色、生成摘要、按提示词生成新内容并回填（受 editor_polish / editor_summary / editor_generate 功能点控制）。
  - **SEO/GEO 配置区「AI 生成 SEO」**：基于标题/摘要/正文/图片标识，AI 一键生成 SEO 标题、描述、关键词三行回填（受 editor_summary 功能点控制）。
  - **图片字段「占位配图」**：输入主题关键词 → 生成免费占位图 URL 一键填入（受 image_placeholder 功能点控制；语义 AI 生图可接入第三方图像服务商）。
- **模型与密钥**：统一走 AI 能力网关（DeepSeek），密钥读取顺序：AI 全局配置 → AI 文本插件配置(apiKey) → 翻译配置 → AI 客服配置。
- **存储**：功能点开关存 `site_config.ai_feature_state`（Json）；`lib/ai/features.ts` 注册表 + `aiFeatureEnabled(key)` 判断；`/api/ai/feature` 服务端统一鉴权调用（未开返回 403 并提示去矩阵开启）。

## 12. AI 自动运营（内容自动生产 + 多语 + 发布流水线）

> 升华落地：把「采集 → AI 补全 → AI 翻译 → 发布 → 推送」串成一条**自动运营流水线**，内容类型草稿自动加工，实现网站自动更新运营。

- **入口**：后台 → 内容工具 → **AI 自动运营**。
- **流水线**：取「内容类型」草稿（如 合作伙伴/荣誉/团队/自定义类型）→ AI 补全缺失的中文字段 → AI 翻译目标语种（英/日/韩/法/阿）→ 按配置自动发布或存草稿待审 → 发布后百度推送。
- **配置项**：
  - 目标内容类型（下拉列出全部动态内容类型及各自草稿数）。
  - 目标语种（多选，仅补全缺失语种，已有内容不覆盖）。
  - 每轮最多处理 1-20 条。
  - 「AI 处理后自动发布」：开启=直接发布；关闭=AI 加工后仍存草稿，人工审核后再发布。
- **运行方式**：点击「立即运行一轮」手动触发；运行结果显示 处理/发布/更新/跳过/错误 统计 + 逐条状态（AI 生成结果可查库或编辑确认）。
- **三层开关**：需 插件管理启用 **AI 自动运营** 插件 + AI 开关矩阵开启 **采集 AI 处理** 功能点 + 全局 AI 打开（任一未开返回 403 并提示）。
- **存储**：配置存 `site_config.ai_autopilot_config`；逻辑在 `lib/ai/autopilot.ts`；API `/api/admin/ai-autopilot`（GET 配置/ POST save / run / stats）。
- **扩展**：未来可接入定时调度（每日/每周自动跑）、采集任务对接（采集落草稿后自动加工发布）。

## 14. 产品增强型内容类型 & 能力市场三优化（2026-09-05）

## R4 深化：API 网关计费 + 多站点数据隔离（2026-09-05）

### 对外 API 网关（能力市场 → API 网关）
- 第三方系统通过 /api/integration/[capability] 调用公开能力（翻译/文本AI/邮件等），统一鉴权（X-API-Key）、限流（每 key 每分钟 60 次）、计费（credits 积分制）、审计。
- **新建 Key**：填用途说明 + 初始积分（留空=不限），生成 zw_ 开头密钥；可复制完整 Key 给第三方。
- **计费**：translate.text 按次1积分+每100字符1积分；ai.text 按次10积分；mail.send 按封1积分；seo.push 按次5积分。余额不足时网关返回 402 并提示所需积分。
- **充值/吊销**：列表内可对某 Key 充值（改余额）或吊销；累计调用/累计消耗/最近使用一目了然。
- **单价展示**：能力单价表显示默认价与来源（默认/自定义），可扩展自定义单价配置。

### 多站点数据隔离（多租户）
- 每个站点（Site）的内容按 siteId 隔离：`null` 表示全局共享（所有站点可见，历史内容默认如此）；指定 siteId 的内容仅对应站点可见。
- 前台列表/详情（产品/新闻/资源/行业/职位/服务）自动按访问域名解析站点并过滤：「全局 + 本站」内容可见。
- 用法：在站点管理为某站点绑定域名后，用该域名访问即看到该站点的专属内容组合；不同站点可展示不同内容体系，一套后台多站运营。
- 说明：后台新建内容默认归属全局（所有站点可见）；若需站点专属内容，需在数据层指定 siteId（开发侧能力，后续可扩展后台「发布到站点」选择器）。

## 在线商城（在线商城插件）

### 功能总览
- 前台 /shop：商品卡片列表（价格/单位/库存/封面/六语种名称摘要/推荐 HOT 标），加购入购物车（localStorage shop_cart）；有购物车内容时右下浮动"购物车"按钮显示数量徽标（与考察预约/询价车浮钮并排，不重叠）。
- 商品详情 /shop/[slug]：大图+六语种详情+数量选择+加入购物车/立即下单（立即下单=加购后跳购物车）；价格为空的商品显示"面议"。
- 购物车 /shop/cart：数量增减/删除/合计/去结算；结算 /shop/checkout：姓名/电话/邮箱/公司/地址/备注+支付方式（线下转账/对公汇款/联系销售/微信支付/支付宝，记录意向不接网关），提交后显示订单号并清空购物车。
- 查单 /shop/order/[orderNo]：按订单号查询状态（待确认→已确认→已完成→已取消）。
- 后台「能力市场→在线商城」：商品管理（CRUD+六语种+价格/库存/推荐/上下架）、订单管理（筛选/搜索/CSV 导出含 IP 地区/状态流转）。

### 使用说明
1. 后台「能力市场 → 插件启停中心 → 在线商城」确认已启用；商品管理/订单管理入口在侧边栏「能力市场 → 在线商城」展开后可见。
2. 商品管理 → 新增商品：填六语种名称/摘要/详情、封面图 URL、售价（留空=面议）、划线原价、单位、库存（-1=不限量）、最小起订、推荐开关、上下架状态，保存后前台即显示。
3. 订单管理：客户提交订单后进入"待确认"，确认→已确认→（线下收款后）已完成；可取消。CSV 导出含客户 IP/国家/城市。
4. 前台结算必填：姓名/电话/邮箱；公司名/地址/备注选填。订单金额以服务器商品价格为准（前端价不可信）。

### 常见问题
- 问：商城商品不上架怎么处理？答：状态选"draft"保存即下架，前台不可见。
- 问：微信/支付宝支付提交后扣款吗？答：不扣款，仅记录意向支付方式，销售顾问线下联系确认收款。
- 问：购物车数据在哪？答：浏览器 localStorage shop_cart，清缓存会清空。


### 订单通知与库存（深化三十四）
- 客户提交订单后：系统自动发送订单确认邮件到客户邮箱（含商品明细/金额/查单链接）；同时发送新订单通知邮件到商家邮箱（info@zuowentech.com，可在服务器环境变量 SHOP_ORDER_NOTICE_EMAIL 修改）。
- 后台订单状态变更（确认/完成/取消）后：自动发送状态更新邮件通知客户。
- 若后台未配置 SMTP（系统设置 → SMTP 邮件），邮件不会真正发出，仅记录服务器日志，下单流程不受影响；配置 SMTP 后即自动启用邮件通知。
- 库存：商品库存设为 -1 表示不限量；设为具体数字时，前台下单会实时校验库存并在下单时扣减（并发下单不会超卖）。库存不足时提示剩余数量。订单取消会自动回补库存（见下方深化三十五）；订单完成不回补。


### 商城体验细节（深化三十五）
- 商品多图：后台商品编辑页可填"多图 URL（每行一张）"，保存后前台商品详情页显示画廊（主图+缩略图切换）；未填多图时自动使用封面图，两者都无则显示占位。
- 取消订单回补库存：后台订单管理把订单状态改为"已取消"时，系统自动把该订单占用的库存加回商品（不限量商品即库存 -1 不参与回补）；已取消的订单再次取消不会重复回补。
- 会员忘记密码：前台会员登录页点"忘记密码"→ 输入注册邮箱 → 收到邮件验证码（后台未配置 SMTP 时验证码直接显示在页面提示中，仅开发模式）→ 输入验证码+新密码完成重置。发送验证码有 60 秒冷却、验证码 10 分钟有效。
- 服务器 SMTP 已配置（腾讯企业邮），忘记密码/订单通知/留言通知邮件均走真实通道。

### 商城分类与阶梯价（深化三十六）
- 商品分类：后台「能力市场 → 在线商城 → 商品分类」管理分类（六语种名称/slug/排序）。商品编辑页可选所属分类；前台 /shop 顶部出现分类 Tab，点击筛选该分类商品。
- 阶梯价（批量价）：商品编辑页可添加多档「达到数量 → 档位单价」（如 2 件以上 ¥899/件、5 件以上 ¥799/件）。前台详情页数量选择实时联动单价并高亮命中档位；购物车/结算页按档位价计算行价与合计；下单金额以服务器按数量计算的档位价为准。
- 删除分类时若分类下还有商品会提示先移除商品。

### 订单发货信息与查单（深化三十七）
1. 订单确认后，后台【商城订单管理】打开订单详情，可填写物流公司、物流单号并保存，系统自动记录发货时间。

### 商城优惠券系统（深化三十九）

**后台发券**：后台 → 能力市场 → 商城 → 优惠券管理。支持两类券：满减券（满 X 元减 Y 元，需设使用门槛）与折扣券（如 9 折，可设最高优惠封顶）。可配置券码（留空自动生成 8 位码）、名称（六语种）、有效期（起止时间，可留空=长期）、发行总量（0=不限量）、每人限领张数、启用/停用。删除券前系统自动清理已领取记录。

**前台领券**：商城页右上角【领券中心】进入。需登录会员后领取（未登录显示登录引导）；每张券显示面额、门槛、剩余数量、有效期与限领说明；已领取的券可再次领取直到达限。

**购物车用券**：购物车结算区显示「优惠券」块——列出当前订单金额下可用的券（自动过滤未领/门槛不足/已用/过期），点击选择后立即显示优惠金额与实付金额；「不使用」可取消。选择会随浏览器记住，结算页自动带入。

**下单与核销**：提交订单时服务端权威校验（券存在、启用中、有效期内、本人已领未用、金额达门槛），计算优惠并记录到订单（订单详情展示券码与优惠金额，实付=商品合计-优惠）。一张券只能使用一次；订单取消不退回优惠券。

**会员我的优惠券**：会员中心新增「我的优惠券」卡，展示已领券的状态（可使用/已使用/已过期）、券码、面额与使用订单号。

**销售统计口径**：商城销售统计的销售额按「实付金额」（商品合计-优惠）计算。

### 优惠券 · B2B 定向发券模式（推荐用法）

企业商城定位为「产品目录 + 询价留资」，优惠券推荐**销售定向发券**模式：

1. 后台「优惠券管理」创建满减/折扣券（可设门槛、封顶、有效期、发行总量）。
2. 销售将券码通过微信/邮件等方式定向发给目标客户（无需客户先注册或领取）。
3. 客户在购物车结算区的**「输入优惠券码」**框粘贴券码，点击应用即时显示优惠与实付金额。
4. 提交订单时服务端权威核销：未登录游客可直接用券；登录会员自动记录核销状态；券有总量上限时先到先得。

领券中心（商城页右上角入口）保留为自助渠道，客户也可自行领取后使用。

## 系统更新（在线/离线增量升级）

后台「系统运维 → 系统更新」为客户自助更新入口。

- **检查更新**：点击后读取本地版本，并向 .env 中配置的 `UPDATE_SERVER_URL`（供应商更新服务器）请求最新版本列表。
- **在线升级**：选中可用版本 →「下载并应用」：系统下载增量更新包 → 校验 MD5 → 解压 → 按 manifest 覆盖对应代码文件。含数据库变更的版本会提示手动执行 `npx prisma db push` 后重启服务。
- **离线升级**：供应商直接发送增量更新包（zip，含 manifest.json）→ 本页上传，自动应用。
- **安全边界**：更新包解压时自动排除 `.env`、`node_modules`、`.next`、`public/uploads`、`data`、`license-keys`、`_pgsql` 等运行期/密钥/客户数据目录，不会覆盖客户数据。
- **建议**：更新前先在「系统运维 → 数据库备份」做一次备份；供应商侧生成增量包见 docs/backend/增量更新说明（scripts/_make_incremental_update.js + scripts/update-server.js）。

## AI 客服知识库 · 全网大数据收集

后台「AI 客服知识库」生成区现支持两种生成方式：

1. **AI 生成**：输入行业/产品关键词，AI 基于行业常识生成「问题+答案」问答对。
2. **全网收集生成**（新增）：输入关键词后，系统先从搜索引擎（必应优先、百度降级）抓取全网相关素材（标题/摘要/来源链接，含相关性过滤），再由 AI 基于素材整理为**带来源链接**的问答对入库，供 AI 客服引用。
   - 未抓到有效素材时自动降级为 AI 常识生成，并在答案中注明"基于行业常识整理，建议核实最新信息"。
   - 生成条目后可用「批量翻译」补齐多语言。

## 供应商发布增量更新（运营手册）

1. **生成增量包**（供应商本机，项目根目录）：
   - 基线法：`node scripts/_make_incremental_update.js --gen-baseline updates/baseline.json` 记录"已发布版本"指纹；下次发布 `node scripts/_make_incremental_update.js --version 1.1.0 --baseline updates/baseline.json --include-migration --release-notes "更新说明"`。
   - 目录对比法：`--prev <上版本项目目录>` 替代 `--baseline`。
   - 产物：`updates/downloads/zuowen-update-<版本>.zip`（manifest.json + 变化文件 + 迁移脚本）。**自动排除** .env/node_modules/.next/uploads/data/license-keys 及全部 .node 平台二进制；**自动把新版本号写入包内 package.json**（客户应用后版本号同步，不会误报更新）；schema 变化加 `--include-migration` 自动附 prisma db push 迁移脚本。
2. **托管更新服务器**：`node scripts/update-server.js 8787`（updates/downloads/ 放包、updates/updates.json 登记版本：`[{"version":"1.1.0","releaseNotes":"...","file":"zuowen-update-1.1.0.zip","publishedAt":"2026-09-06"}]`）；Nginx 反代公网域名（如 updates.zuowen.com）。
3. **客户侧**：.env 配 `UPDATE_SERVER_URL=https://更新服务器域名` → 后台「系统运维 → 系统更新」检查更新/下载并应用；或直接上传离线包。
4. **已实测闭环**（2026-09-06）：0.1.0 → 检查 → 下载 532MB → 应用 517 文件 → 本地版本同步 0.2.0 → 复查无误报。
