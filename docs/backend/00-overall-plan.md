## 1. 项目背景与目标

### 1.1 背景

左文科技官网当前为 **Next.js 14 静态数据驱动**的前端站点，所有内容（产品、行业、服务、资源、新闻、关于、职位、配色、轮播图等）均硬编码在 `lib/*.ts` 静态文件与组件中。站点已具备多语言、360° 产品旋转查看、下载邮箱验证等动态能力，但**缺乏内容管理能力**，内容更新需要修改代码、重新发布。

### 1.2 目标

1. **后台可管理一切内容**：前端所有内容（含配色、360 旋转帧图、下载文件、轮播、统计数据）均可在后台修改，无需改代码。
2. **企业官网定位**：更新频率不高（周更/月更为主），后台需**轻量、易用、稳定**，避免过度复杂。
3. **SEO 与 GEO 双优**：页面天然适合搜索引擎与生成式 AI 引擎（AI Overviews / Perplexity / 文心 / 豆包等）快速长期收录。
4. **完整后台功能**：标准「左导航 + 右内容」布局，支持**管理员**与**内容维护人员**两类角色及权限管理。
5. **新闻智能化**：新闻栏目支持**定时采集**，可**对接大模型接口**完成内容清洗、翻译、摘要、打标等维护工作。
6. **双域部署**：可部署于**阿里云（国内主站）**与**美国服务器（海外镜像）**，数据与内容同步。

### 1.3 范围界定

- **本期范围**：后台管理系统（内容管理、用户权限、系统配置、主题配色、采集与大模型接入、留资数据、操作日志）+ 前端可配置化改造 + SEO/GEO 优化 + 部署方案。
- **不在本期**：电商交易、在线支付、会员体系、多租户（单站单租户）。

### 2.3 前端已有动态能力（后台需对接）

1. **360° 旋转查看**（`components/ui/ThreeSixtyViewer.tsx`）
   - 依赖 `imagePathTemplate`（如 `/images/360/zw-10d/Frame{index}.png`）+ `totalFrames` 帧数。
   - 后台需支持：上传 360 帧图序列 → 自动生成路径模板与帧数 → 前端读取渲染。
2. **下载验证门禁**（`components/ui/DownloadGateModal.tsx` + `app/api/download/*`）
   - 已实现：姓名/公司/手机/邮箱表单 + 邮箱验证码（发送接口 `/api/download/send-code`，验证接口 `/api/download/verify`）。
   - 当前：验证通过仅写 localStorage（7 天有效），**留资数据未入库**。
   - 后台需支持：留资数据入库、后台查看/导出、验证码发送接入真实 SMTP。
3. **多语言 i18n**（`lib/i18n.tsx` + `config/i18n.ts`）
   - localStorage 持久化；所有内容实体均含中英文字段。
4. **全站搜索**（Header 内联搜索，数据源为前端静态数据）
   - 后台数据化后，搜索数据源需切换为 API/索引。

## 3. 总体架构设计

### 3.1 架构决策原则

- **单一代码库演进**：在现有 Next.js 项目中增加 `/admin` 后台模块，复用现有组件与数据模型，避免双系统运维成本。符合"官网更新频率不高"的定位。
- **前后端一体但分层清晰**：后台管理 API（`/api/admin/*`）与前台渲染 API（`/api/public/*`）分离；管理端为 SPA 风格页面。
- **数据库驱动内容**：将 `lib/*.ts` 静态数据迁移为数据库内容 + 前端运行时读取，保留"无内容时回退静态数据"的双保险。
- **配置可注入**：主题配色、站点信息等通过**运行时配置表** + **CSS 变量**实现"后台改、前端即时生效"。

### 3.2 逻辑架构

```

│  │ 前台渲染层   │  │ 后台管理端    │  │  API 层           │   │
```

### 3.3 模块划分

| 模块 | 说明 |
|------|------|
| 前台展示层 | 现有全部页面改造为数据驱动（读取 API/DB），保留 SSG/SSR |
| 后台管理端 `/admin` | 登录、Dashboard、内容管理、用户权限、系统配置、主题设置、采集管理、留资/统计、操作日志 |
| 公开 API `/api/public/*` | 前台页面取数（产品/新闻/资源/配置/主题等），支持缓存 |
| 管理 API `/api/admin/*` | 后台 CRUD（统一鉴权 + RBAC + 操作日志） |
| 下载 API `/api/download/*` | 验证码发送/校验、留资入库、文件下载（鉴权） |
| 采集与 AI 服务 | RSS 定时采集、大模型清洗/翻译/摘要/打标、草稿审核发布 |
| 同步与部署 | 主站/镜像站代码同步、数据主从、CDN 刷新、CI/CD |

## 4. 技术选型

> 选型原则：企业官网、低更新频率、可长期维护、双域部署、成本可控。

| 层 | 选型 | 版本 | 说明 |
|----|------|------|------|
| 前端框架 | Next.js（沿用） | 14.x | App Router、RSC、SSR/SSG |
| 语言 | TypeScript（沿用） | 5.x | 类型安全 |
| 样式 | Tailwind CSS（沿用） | 3.x | 需做配色 CSS 变量化改造 |
| ORM | Prisma | 5.x | 类型安全、迁移管理、多数据库支持 |
| 数据库 | PostgreSQL | 15+ | 生产；开发可用 SQLite（Prisma 无缝切换） |
| 鉴权 | Auth.js (NextAuth) | v5 | Credentials + JWT Session + RBAC 角色 |
| 后台组件 | 自建轻量组件 + shadcn/ui | - | 左导航右内容标准后台布局 |
| 文件存储 | S3 兼容对象存储 | - | 阿里云 OSS（国内）/ AWS S3 或 MinIO（海外），统一 S3 SDK |
| 邮件 | SMTP | - | 阿里云邮件推送（国内）/ AWS SES（海外） |
| 定时任务 | node-cron（应用内）+ 平台 Cron | - | 采集/发布/备份 |
| 大模型 | 火山方舟豆包（国内）/ OpenAI 兼容（海外） | - | 内容清洗、翻译、摘要、打标、生成 |
| 缓存 | 应用内内存缓存（首期） | - | 官网规模暂不引入 Redis，预留接口 |
| 数据备份 | pg_dump + 对象存储归档 | - | 每日自动备份 |

### 4.1 关键选型理由

- **沿用 Next.js 而非新建后端**：单仓库部署简单、复用现有 16 个页面与组件、SSR/SSG 对 SEO 天然友好；符合"更新频率不高"。
- **PostgreSQL + Prisma**：成熟稳定、云上托管（RDS）与自建均可，Prisma 迁移机制保证双域部署一致。
- **S3 兼容存储统一抽象**：国内 OSS 与海外 S3 均兼容 S3 API，代码零改动切换，满足镜像部署。
- **Auth.js**：Next.js 官方生态、支持 RBAC、Session 可持久化到 PostgreSQL（适配多实例部署）。

### 5.2 角色与权限（RBAC）

| 角色 | 代号 | 权限范围 |
|------|------|----------|
| 超级管理员 | `admin` | 全部权限（含用户/角色管理、系统配置、主题、采集、删除、数据导出） |
| 内容维护人员 | `editor` | 内容管理（产品/行业/服务/资源/新闻/关于/职位/留言）、草稿审核发布；**不可**：用户管理、系统配置、主题、删除（仅软删）、敏感操作 |

权限粒度采用「**菜单权限 + 操作权限**」两级：
- 菜单权限：控制左侧导航可见菜单。
- 操作权限：`create / read / update / delete / publish / export` 每资源独立配置。
- 权限在 `role_permission` 表中维护，中间件在 API 层强制校验（不仅前端隐藏）。

### 5.3 功能模块明细

#### 5.3.1 控制台 Dashboard
- 内容概览计数（产品/新闻/资源/职位等）。
- 近 30 天新增新闻、留资线索趋势。
- 待审核草稿、采集失败任务提醒。
- 系统健康（数据库连接、存储用量、定时任务状态）。

#### 5.3.2 产品管理（核心）
- 三级结构：**产品系列 Tab → 分类 Category → 型号 Model**（对应现有 `productTabs`）。
- 每个型号可管理：名称（中/英）、型号 code、主图、图集、**360 帧图（多文件上传，自动生成模板与帧数）**、规格表（动态键值）、特性、详情富文本（中/英）、**产品手册下载文件**。
- 支持排序、上架/下架、复制、软删除。

#### 5.3.3 应用领域 / 服务 / 关于 / 职位管理
- 结构化表单（中英文字段、列表字段、富文本）。
- 排序与启用状态。

#### 5.3.4 资源下载管理
- 分类管理（样本/证书/图纸）+ 条目管理。
- 每个条目：标题、描述、格式、大小、日期、**下载文件上传**。
- 支持**灰色禁用态**（无文件时下载按钮灰色，已有逻辑保留）。
- 下载权限开关（是否需要验证）。

#### 5.3.5 新闻管理（含采集）
- 手动新增/编辑新闻（中英双语、摘要、正文段落、精选标记、分类、发布日期、SEO 标题/描述）。
- **定时采集**：配置 RSS/网页采集源 → 定时抓取 → 大模型清洗/翻译/摘要/打标 → 生成**草稿** → 人工审核发布。
- 发布管理：草稿/已发布/已下架；定时发布。
- 防重复（URL 去重、标题相似度）。

#### 5.3.6 留言与留资管理
- 联系表单留言列表、状态（新/已处理）。
- 下载留资列表（姓名/公司/手机/邮箱/下载资源/时间），支持导出 CSV。

#### 5.3.7 用户与权限
- 用户 CRUD、分配角色、启用/禁用、重置密码。
- 角色与权限配置。

#### 5.3.8 系统设置
- **站点配置**：联系方式、地址、页脚信息、备案号、Logo、SEO 默认值。
- **主题设置（配色）**：主色 primary、点缀色 accent、深色系 dark（含各明度阶），后台修改 → 存配置表 → 前端 CSS 变量注入即时生效。
- **首页配置**：Hero 轮播（标题/副标题/背景渐变/按钮）、统计数据、区块显隐。
- **采集配置**：采集源、频率、目标分类、大模型参数。
- **大模型配置**：API Key、BaseURL、模型名、翻译/摘要 Prompt 模板。

#### 5.3.9 系统运维
- 操作日志（谁在何时做了什么）。
- 缓存清理（内容/主题缓存）。
- 数据备份（手动触发 + 查看备份列表）。
- 双站同步状态。

#### 5.3.10 系统更新
> 2026-08-30 新增需求：后台具备系统更新与版本管理能力。

- **版本信息**：当前系统版本号、发布日期、构建时间、Git commit、运行环境（生产/测试）。
- **更新日志（Changelog）**：按版本倒序列出每次发布的功能新增、优化、修复内容；支持后台手动录入新版本日志。
- **检查更新**：连接更新服务器（或本地版本文件）检查是否有新版本；显示新版本号与更新内容摘要（自托管系统可选启用）。
- **系统状态监控**：
  - 应用服务状态（运行中/异常，运行时长，内存/CPU 占用）
  - 数据库连接状态（连接数、慢查询数）
  - 存储使用情况（OSS/S3 已用容量、文件数）
  - 缓存状态（命中率、键数）
  - 定时任务状态（最近执行时间、成功/失败）
- **维护操作**：
  - 一键清理缓存（内容缓存、主题缓存、静态资源缓存）
  - 重建搜索索引
  - 手动触发数据备份
  - 查看备份列表与恢复入口
- **环境信息**：Node.js 版本、Next.js 版本、PostgreSQL 版本、Prisma 版本、操作系统、服务器时区。
- **权限**：仅 `admin` 角色可访问；`editor` 不可见。

## 6. 前端可配置化改造方案（关键）

> 这是"后台可改前端一切"的核心技术工作，涉及三块：**内容数据化**、**配色变量化**、**动态功能（360/下载）可管理化**。

### 6.1 内容数据化（数据源切换）

**目标**：前端页面从「读取 `lib/*.ts` 静态数据」改为「读取数据库内容」。

**改造方式**：
1. 将 `lib/products.ts`、`lib/industries.ts`、`lib/resources.ts`、`lib/news.ts`、`lib/about.ts`、`lib/careers.ts` 的数据**迁移为数据库种子数据**（首次建库自动灌入）。
2. 新增公开 API：`/api/public/products`、`/api/public/news`、`/api/public/resources`、`/api/public/config` 等。
3. 页面改造为服务端取数：`async function Page() { const data = await getContent('products'); ... }`，保留 ISR（增量静态再生成）保证 SEO 与性能。
4. **回退机制**：数据库为空或请求失败时回退到内置静态数据，保证站点永不白屏。
5. `lib/*.ts` 保留为「默认种子/兜底数据」与「类型定义」来源。

**涉及页面**：16 个页面路由全部覆盖（见 2.1 表）。

### 6.2 配色变量化（主题可后台修改）

**目标**：后台改配色 → 前端全站即时生效（含 SSR 首屏）。

**改造方式**：
1. `tailwind.config.ts` 颜色改为引用 CSS 变量：
   ```ts
   primary: {
     DEFAULT: "rgb(var(--color-primary) / <alpha-value>)",
     light: "rgb(var(--color-primary-light) / <alpha-value>)",
     dark: "rgb(var(--color-primary-dark) / <alpha-value>)",
     // 各明度阶同理
   },
   accent: { DEFAULT: "rgb(var(--color-accent) / <alpha-value>)", ... },
   dark: { DEFAULT: "rgb(var(--color-dark) / <alpha-value>)", ... },
   ```
2. 根布局 `<html>` 从 `theme_config` 表读取色值，SSR 内联注入 `:root { --color-primary: 204 0 0; ... }`。
3. 后台「主题设置」修改色值 → 更新 `theme_config` 表 → 触发 CDN 刷新 → 前端更新。
4. 未配置时使用默认色（当前 #CC0000 红色系），保证兼容。

**注意事项**：现有组件中少量硬编码色值（如 `Hero.tsx` 的 `bgGradient` 渐变色、`#800000` 等）需一并改为配置项或变量，列入改造清单。

### 6.3 360 旋转可管理化

**现状**：`ThreeSixtyViewer` 接收 `imagePathTemplate` + `totalFrames`，数据来自产品数据的 `frames360` 字段（当前部分产品硬编码）。

**改造方式**：
1. 产品表新增 `frames360` 字段：`{ template: "/images/360/{slug}/Frame{index}.png", totalFrames: 60, startIndex: 1 }`。
2. 后台产品编辑页提供「360 帧图管理」：批量上传帧图（自动命名 `Frame000001.png`…）、预览、设置帧数/模板、上传到 OSS/S3。
3. 前端产品详情页从 API 读取 `frames360` 配置传给 `ThreeSixtyViewer`。
4. 兼容：未配置 360 的产品不显示 360 模块（现状逻辑）。

### 6.4 下载资源可管理化

**现状**：资源条目的 `downloadUrl` 硬编码（部分为 `#` 灰色禁用）；验证通过后仅写 localStorage。

**改造方式**：
1. 资源表管理 `downloadUrl`：后台上传文件到 OSS/S3，保存对象 URL；无文件时保持 `#` → 前端灰色禁用态（已有逻辑）。
2. 验证码真实化：`/api/download/send-code` 接入 SMTP 发信；验证码存库（`verify_code` 表，5 分钟有效）。
3. 验证通过后**留资入库**（`download_lead` 表），并写 `verified_at` 返回；前端仍以 localStorage 缓存 7 天（可用性），后台以 DB 为准做统计。
4. 文件下载走鉴权（可选：签名 URL 有效期），下载行为记录日志。

## 7. SEO 与 GEO 优化方案

### 7.1 SEO（搜索引擎优化）

| 项 | 方案 |
|----|------|
| 渲染 | 全站 SSR/SSG（Next.js 服务端渲染），关键页静态化（ISR）保证收录速度 |
| 元数据 | 每个页面独立 `metadata`（title/description/keywords/canonical/OG/Twitter），后台可维护 |
| 结构化数据 | JSON-LD：`Organization`、`Product`、`NewsArticle`、`BreadcrumbList`、`FAQPage`（行业页） |
| Sitemap | `sitemap.xml` 全站动态生成（含中英文 hreflang） |
| Robots | `robots.txt` 正确放行、标注 sitemap |
| Hreflang | 中英文页面互指（`zh-CN`/`en`） |
| 性能 | 图片 next/image 优化、360 帧图懒加载、Core Web Vitals 达标 |
| 404/301 | 自定义 404、内容下架 301 到相关页 |
| 内链 | 面包屑、产品↔行业互链、新闻详情相关推荐 |

### 7.2 GEO（生成式引擎优化，面向 AI 搜索/答案引擎）

> GEO = Generative Engine Optimization：优化内容使其被 AI 搜索引擎（Google AI Overviews、Perplexity、文心一言、豆包、Kimi 等）准确引用与推荐。

| 项 | 方案 |
|----|------|
| 实体清晰化 | 全站统一「公司名/品牌/联系方式/地址/资质/产品型号」事实，与全网公开信息一致（名称拼写、联系方式、地址统一） |
| 结构化事实 | 产品规格用**表格**呈现（参数名=参数值），便于 AI 抽取 |
| FAQ 区块 | 行业/产品页内置 FAQ（问题+简明答案），触发 FAQ 结构化数据 |
| 可引用摘要 | 每类内容提供 2-3 句「标准事实陈述」（excerpt），作为 AI 引用源 |
| 纯文本可达 | 关键信息不依赖图片/JS，AI 爬虫可直接读取 HTML 文本 |
| 权威信号 | 保持 about 页完整法人信息、资质证书、专利、新闻时间线 |
| 术语一致性 | 中英文术语全站统一（MPCVD、培育钻石、金刚石等），利于语义关联 |
| 内容新鲜度 | 新闻定时采集 + 定期发布，保持站点活跃度（GEO 权重信号） |
| 链接可引用 | 每个内容页 URL 稳定、可直达（不使用 hash 承载关键内容） |

## 8. 新闻定时采集与大模型对接

### 8.1 采集流程

```
采集源配置(RSS/网页)
      │  Cron 定时触发（node-cron / 平台 cron）
      ▼
抓取原始内容（超时/去重/编码处理）
      │
      ▼
大模型预处理（火山方舟豆包 / OpenAI 兼容）
      ├─ 内容清洗（去广告、去噪、规范格式）
      ├─ 简体中文整理 + 英文翻译
      ├─ 自动摘要（excerpt）
      ├─ 智能分类 + 关键词打标
      └─ 合规过滤（敏感词/来源可信度）
      │
      ▼
生成【草稿】入库（标记来源URL/采集时间/原文链接）
      │
      ▼
人工审核 → 修改/确认 → 发布（或定时发布）
```

### 8.2 采集源管理

- 支持 RSS 2.0 / Atom 与简单网页抓取（Cheerio）。
- 采集源字段：名称、URL、类型、目标分类、抓取频率、启用状态、最近抓取时间、最近失败原因。
- 去重：URL 去重 + 标题相似度（simhash/编辑距离）防重复入库。

### 8.3 大模型对接设计

| 场景 | 调用方式 | 输出 |
|------|----------|------|
| 清洗 | LLM：输入原文 → 输出干净正文 | 结构化正文 |
| 摘要 | LLM：输入正文 → 输出 2-3 句摘要 | excerpt |
| 翻译 | LLM：中文正文 → 英文正文/摘要 | contentEn/excerptEn |
| 打标分类 | LLM：输入标题+正文 → 输出分类+关键词 | category/tags |
| 合规 | LLM/规则：敏感词 + 来源判断 | 标记风险 |

- 接口抽象：`lib/llm/client.ts` 封装统一 `chat()` 方法，国内用火山方舟豆包，海外用 OpenAI 兼容地址，可配置切换。
- 全部 LLM 输出均进入**草稿**，人工审核后方发布（合规与质量红线）。
- LLM 调用失败自动重试（指数退避），不阻塞主流程。

### 8.4 定时任务清单（Cron）

| 任务 | 频率 | 说明 |
|------|------|------|
| 新闻采集 | 每 6 小时 | 抓取启用采集源，入库草稿 |
| 定时发布 | 每分钟检查 | 发布到达时间的草稿 |
| 验证码清理 | 每小时 | 清理过期验证码 |
| 数据备份 | 每日 03:00 | pg_dump 归档 OSS/S3 |
| 会话清理 | 每日 | 清理过期 Session |
| 缓存刷新 | 内容变更时 | CDN 刷新 + 应用缓存清理 |

## 9. 部署方案（阿里云 + 美国镜像）

### 9.1 目标拓扑

```
                       ┌──────────────────────────────┐
  国内用户 ──→ 阿里云CDN ──→ 阿里云 ECS（主站）          │
                              ├─ PostgreSQL RDS（主）   │
                              ├─ 阿里云 OSS（静态资源）  │
                              ├─ 阿里云邮件推送（SMTP）  │
                              └─ 火山方舟（大模型）      │
                       ┌──────────────────────────────┐
  海外用户 ──→ CloudFront ──→ 美国 EC2/ECS（镜像站）     │
                              ├─ RDS 从库（同步主库）    │
                              ├─ S3（静态资源镜像同步）   │
                              ├─ AWS SES（邮件）        │
                              └─ OpenAI 兼容（大模型）   │
                       └──────────────────────────────┘
```

### 9.2 双域数据与内容同步

| 同步项 | 方案 |
|--------|------|
| 数据库 | 主站 RDS 为**主库**，美国 RDS 为**只读从库**（PostgreSQL 流复制）；内容维护只在主库执行 |
| 静态资源 | OSS 与 S3 通过**跨区域复制**（OSS 跨区域复制 → 自建 S3；或代码上传时双写） |
| 代码 | 单仓库，CI 构建产物分别部署两站 |
| 内容发布 | 发布动作发生在主站；从库自动同步；镜像站只读展示 |
| 域名 | 国内域名（.com 已备案）+ 海外访问同一域名经 CDN 智能 DNS 分流 |

### 9.3 环境与配置

- `.env` 按环境管理（`.env.production-cn` / `.env.production-us`），密钥入 CI Secrets。
- 数据库、OSS、邮件、大模型均通过环境变量注入，代码零差异。

### 9.4 CI/CD

- GitHub Actions：push main → lint/test/build → 分别部署阿里云（镜像上传 ACR + ECS 滚动）与美国（Docker → ECS/EC2）。
- 数据库迁移：部署前执行 `prisma migrate deploy`。
- 内容变更触发 CDN 刷新（API 内调 CDN 刷新接口）。

### 9.5 基础设施清单（建议配置）

| 资源 | 建议规格 | 说明 |
|------|----------|------|
| 阿里云 ECS | 2C4G（首期） | Next.js 应用 |
| 阿里云 RDS PostgreSQL | 2C4G 50G | 主库 |
| 阿里云 OSS | 按量 | 静态资源/帧图/下载文件 |
| 阿里云 CDN | 按量 | 全站加速 |
| 美国 EC2 | t3.medium | 镜像站应用 |
| 美国 RDS 从库 | db.t3.small | 只读从库 |
| S3 + CloudFront | 按量 | 海外静态资源 |
| 邮件服务 | 按量 | 验证码/通知 |

## 10. 安全与合规

- **鉴权**：Auth.js + JWT Session；管理端所有接口强制 RBAC 校验（服务端，不只前端）。
- **密码**：bcrypt 哈希存储。
- **防注入**：Prisma 参数化查询。
- **上传安全**：文件类型/大小校验、MIME 白名单、随机文件名、禁止可执行文件。
- **验证码**：6 位数字、5 分钟有效、单邮箱限流（60s）、错误次数限制。
- **操作日志**：管理端关键操作全部记录（谁/何时/何操作/前后值）。
- **内容合规**：新闻采集内容人工审核发布；留资数据符合《个人信息保护法》（最小收集、明示用途、可导出删除）。
- **备份**：每日自动备份 + 保留策略；关键操作前可手动备份。
- **HTTPS**：全站强制 HTTPS。
